Grounding contract

Every answer the API returns is accompanied by the passages it was composed from. This page specifies what "grounded" means, what the service guarantees, and what it does when it cannot meet that guarantee.

v4.2 stable

What counts as grounded

A claim is grounded when the service can point to a contiguous span in an indexed document that supports it. Paraphrase is allowed; inference across two passages is not. If a sentence in the response cannot be tied to a span, the sentence is removed before the response is returned — the service does not ship an unsupported sentence with a hedge attached to it.

Note

Grounding is checked after generation, not during. A model that writes a well-supported answer and a model that writes a plausible one are indistinguishable at generation time.

Response shape

Citations are returned as character offsets into answer, not as inline markers, so a client can render them as chips, footnotes or margin notes without parsing prose.

Confidence and refusal

Below the workspace threshold the service returns status: "insufficient_evidence" with the passages it did find, and no answer. A weak answer with a low score attached still reads as an answer, so the service declines to produce one.

Errors

Caution

A 409 means the index is mid-rebuild. Queries keep serving the previous index — retry is safe and returns the old answer, not an error.
