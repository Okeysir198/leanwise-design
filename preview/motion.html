data-ambient="on"on any ancestor: runs every ambient loop (--lw-ambient-play: running). Since v2.0 the default is paused; a page that wants the drifts says so once
data-ambient="off"on any ancestor: every ambient loop parks at frame 0 (--lw-ambient-play: paused) and the sheen hides — for a still subtree inside an opted-in page

Ambient loops are on a scale of their own (v1.13.0). The twenty-one bespoke names that preceded it — --lw-dur-marquee, -wash, -aurora-a/b, -ground, -comb, -breathe, -sheen, -caret and the rest — were removed in v2.0; every loop reads a tier, and an effect that sits between two tiers reads a ratio of one (calc(var(--lw-dur-ambient) * .8)), not a number of its own. Their feel is calibrated to the effect, not to an interaction, which is why they are not on the interaction scale above. The loops are paused by default: a page that wants the drifts writes data-ambient="on" once; the frame a paused loop rests on is the frame it starts from, so the still render is identical.

Enter reveal and spotlight (v3.1)Use
.lw-revealthe element fades and rises as it scrolls in. CSS only — animation-timeline: view(), no hook, no observer, no JavaScript
.lw-reveal-groupthe same, applied to each CHILD in sequence. The index comes from :nth-child, so vanilla HTML gets the identical cascade; capped at 8, the ceiling .lw-flow and useDeterministicCascade already share
[data-reveal]on a .lw-reveal: the state a script sets — "pending" then "shown", e.g. from useReveal(). The attribute is the contract, not the hook, and it wins: the scroll rules stand down so the two never write opacity on one box
--lw-reveal-shiftthe rise distance (default 12px)
.lw-spotlighta pointer-following highlight, the paint for useSpotlight() — which has written --lw-mx / --lw-my since v0.3.2 into a layer that read neither

Nothing is hidden outside a gate. A reveal utility is the easiest way to ship a blank page — hide first, un-hide on an event, and a reader whose event never arrives gets nothing, silently. So the opacity floor lives inside @supports (animation-timeline: view()) and prefers-reduced-motion: no-preference for the CSS path, and inside an attribute the element does not carry until a script adds it for the JS path. No JavaScript, no scroll timelines, or a reduced-motion preference: the static state is the complete state.

The legacy --lw-duration-* aliases were removed in v2.0 — a consumer reads --lw-dur-xs / -sm / -lg directly.

Every animation is wrapped in @media (prefers-reduced-motion: reduce), including the bars above — set that preference and they render complete and still. Motion is an enhancement; nothing may depend on it to convey state.
