TopBar — mobile nav

This is deliberately not Drawer, and the difference is real rather than a naming preference. Drawer is a modal <dialog> promoted to the top layer: it makes the page inert, so it owns a focus trap, a scrim and a return-focus contract. A nav disclosure hangs under the bar, leaves the page visible and interactive, and needs none of that. Two interactions, two components — README rule 9 is about one interaction wearing two treatments, which this is not.

The panel is position: absolute under a position: sticky bar, so the bar is already its containing block and inset-block-start: 100% is the bar's underside. That matters because .lw-topbar carries backdrop-filter, which makes it a containing block for position: fixed descendants too — the consumer's hand-rolled version shipped broken on exactly that, resolving inset: 0 against the 56px bar instead of the viewport and painting its background in that strip alone. Absolute under sticky has no such failure; anything reworked to fixed has to become a sibling of the <header>.

.lw-topbar-panel[hidden] { display: none } is mandatory and fails silently without it. The panel's own display: flex is an author rule, so it outranks the UA's [hidden] default and the panel would stay painted while its attribute said it was hidden. The panel is hidden rather than unmounted, because aria-controls has to point at an element that exists.

why it is built this way

The toggle's display rule is scoped under .lw-topbar, and that is load-bearing. It composes .lw-icon-btn, whose display: inline-flex still lives in product.css — equal specificity, loading after base.css. An unscoped .lw-topbar-toggle { display: none } would lose to it, and the toggle would show on every desktop app page.

The toggle appears in the same frame the links disappear in. Both rules sit at --lw-bp-md (768px) — not because 768 is a nice number, but because a bar whose links have dropped and whose toggle has not yet appeared has no navigation at all.

The accessible name is the ACTION, not the state. aria-expanded already carries the state; a button permanently named “Menu” tells a screen-reader user nothing about what pressing it will now do, so the name flips to “Close menu” while the panel is open. Escape closes and returns focus to the toggle — bound to the two elements rather than to the document, because a non-modal disclosure has no claim on Escape while the reader is somewhere else on the page.
