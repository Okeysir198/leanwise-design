Navigation

Tabs implement roving tabindex. Arrow keys move between tabs, Home/End jump to the ends, and only the selected tab is in the tab order — the part every hand-rolled tab strip skips and the part a keyboard user needs.

Active nav is a tint plus brand ink, never a left accent bar. The rail collapses via data-collapsed — a state on the element rather than a second class, so the width and the label visibility have one source.

This is the app shell's own chrome, not an arrangement invented for the card: the frame owns the rail's width, ground and edge while the nav inside runs data-embedded and fills it — two width owners never agree. The collapse control sits in the bar next to the breadcrumb trail, where the product puts it, and the same nav model appears on every app surface with only current differing.

why it is built this way

Theme toggle

Every state here is real — this is the shipped control, not a mock-up. Segments carry a pointer cursor, a hover tint, a press that scales 3%, and a :focus-visible ring that switches to the brand-400 tier on dark grounds, where the 500 ring disappears into navy. The selected segment is a raised surface plus a hairline in both themes — lighter than its own track either way, so the control reads the same on navy as on white, and the brand fill stays reserved for actions.

On the dark ground that track, pill and hairline come from --lw-on-dark-fill, --lw-on-dark-line and --lw-on-dark-2 rather than raw rgba(255,255,255,·) — that family exists precisely to stop that sprawl, and it is the one token group authored as raw rgba, so brandVars() cannot re-tint it.

Two segments here, because this product ships two themes. The control defaults to three — light / dark / auto — and auto is a real choice worth keeping wherever a product honours it, since a two-state toggle silently overrides prefers-color-scheme forever after the first click. LeanWise app surfaces are authored light and dark, so every one of them passes modes={["light","dark"]} — the supported set is declared, never a third segment hidden with CSS. The resolved theme is applied before first paint, so there is no flash.
