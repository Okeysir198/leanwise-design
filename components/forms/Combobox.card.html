Combobox

Focus stays in the input; the active option is named by aria-activedescendant. That is the ARIA 1.2 combobox pattern, and it is the opposite of Menu — moving real focus into the list would take it out of the field the user is still typing in. Menu has nothing to type into, so there focus moves.

The field is the anchor and the input inside it is bare, so the focus ring wraps the whole control — the same arrangement as InputGroup, for the same reason. Invalid selects on :has([aria-invalid]), never a class. When onSearch is present the component stops filtering locally: the options you pass ARE the result, and filtering them again hides rows the server deliberately returned.
