why it is built this way

Paths, never a font. An icon font ships one glyph height for every icon, fails visibly while it loads, and cannot be recoloured per-path. These are inline SVG on a single 24 grid at a single 1.6 stroke, filled with currentColor — so an icon inherits the ink of whatever it sits in and can never introduce a colour the tokens do not know about.

An unknown name is loud, not silent. A missing glyph renders nothing and leaves layout unchanged, which is exactly how nine blank controls once shipped. Icon warns to the console with the full list of valid names, so a typo is caught the first time the component mounts rather than in a screenshot review.

Size is inline, not a presentation attribute. Any class rule (.lw-btn svg { width: 16px }) outranks a presentation attribute, which silently made size inert inside buttons. The value goes on style so the prop stays authoritative wherever the icon lands.

Decorative by default. Icons are aria-hidden unless you pass label. An icon beside a word is noise to a screen reader; an icon that IS the control needs a name — and the control usually carries it already, via aria-label on the button.
