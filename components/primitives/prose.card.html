Prose & Disclosure

Both panes below render the same markup. The dark one carries .lw-band-dark and nothing else — there is no .lw-band-dark .lw-prose rule anywhere in the package. Every value in the prose block is a ROLE (--lw-fg, --lw-fg-muted, --lw-line, --lw-brand-text, --lw-bg-inset), and a role re-points under the band on its own. That is the whole argument for role-over-tier, rendered rather than asserted: one --lw-text-2 in here and the article would freeze light-mode ink on navy.

The code rule is the one that has already failed a gate. Block code is the always-dark .lw-code surface with its tok-* spans, which the consumer emits itself — so .lw-prose pre gets spacing and nothing else, and the inline chip is guarded to :not(pre) > code. A bare code rule here put a light chip behind that dark surface and check:a11y failed the run. The guard is the rule.

Disclosure is <details>, not a scripted accordion — so the pattern is complete with zero JavaScript and every row opens before hydration, with a failed bundle, or with JS off. There is no height animation and no keyframe: <details> cannot animate its own height portably, and the motion policy is a 100–200ms state change either way. Only the chevron moves, and the chevron is <Icon name="chevron-down"> — never a CSS triangle.

why it is built this way

The owl selector, deliberately. .lw-prose > * + * puts the space on the boundary between two blocks rather than on either block. It is the only form that cannot leave a leading margin on the first child or a trailing one on the last — and because the UA's own block margins are cleared first, the gap is a token rather than an em of whichever element happened to be larger.

scroll-margin-block-start on the headings is load-bearing. .lw-topbar is position: sticky, so without it a #fragment link lands the heading under the bar and the reader arrives at a section whose title is invisible.

Headings are grouped onto the scale, not restated. .lw-h2, .lw-prose h2 is one rule. An authored heading and a markdown ## are the same heading at the same level, and a second copy of the size is a second copy that drifts. h4 takes body size plus semibold and there is deliberately no --lw-text-h4 token — one rule does not justify a scale step, and a token nothing else reads is one the next person misuses.
