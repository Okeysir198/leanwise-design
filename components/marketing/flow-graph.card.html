Flow (branching)

A chain could not draw any of these. Until v1.6.0 edges could only delete links from the sequential chain — a pair that was not adjacent in nodes was silently ignored. That pair now selects this renderer: nodes are laid on a lattice and the connectors are box-drawing tiles, so two inputs can meet, one step can split, and a step can loop back.

a fan-in — two kinds of input meeting, then splitting to two outcomes
a fan-out from the first node — one source, three independent destinations
a loop — routed below every lane and drawn dashed, and named in words in the table
a plain CHAIN, written in the object edge form — still the chain renderer, and it must not throw
why it is built this way

The drawing is not the content

A branching diagram's whole payload is “01 leads to 02 and 03”, and a lattice of bordered cells says that in pixels alone. So every graph also emits an .lw-sr-only successors table — the same device, for the same reason, as the data table under every chart. The connector cells are aria-hidden; the table is the answer. Turn CSS off and the graph is still readable; the chain form never needed that because a chain is its DOM order.

No SVG, and that was the decision

An overlay <svg> sized to a content-driven grid needs either getBoundingClientRect() — JavaScript, on a component that must stay server-safe and must survive with JS disabled — or preserveAspectRatio="none", which shears every stroke and radius. Nodes therefore stay real HTML cards with real text, and the connectors are CSS borders on grid cells: ::before for the horizontal arms, ::after for the vertical ones, sized by which arms the cell has. Eight rules, not eleven named corner classes.

Layered by longest path, not shortest

A node sits one column after its last dependency, which is what makes a merge look like a merge. Shortest path would put the second input of a fan-in in column 0 and drag its connector across the whole diagram. Cycles are detected and routed as loops whether or not they are declared — otherwise the layering never settles.

Under 768px the lattice is abandoned, not shrunk

Eight node columns on a phone is eight one-word cards — the same judgement the chain form already makes. The nodes are emitted in column-major order, so the stack reads in dependency order with no reordering, and branch depth survives as a capped indent. Capped, because an uncapped depth × step is precisely the shrink-to-fit shape that has escaped this system's viewport four times.
