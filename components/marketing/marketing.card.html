Marketing composites

StoryCard will not render a half-filled testimonial. The quote block appears only when quote, person and role are all present — checked at runtime, not documented in a file nobody reads. A quote with no attributable person is an invented one, and the component refuses to help.

One amber CTA per view. The hero below spends it; every other action on the page is cyan or ghost. That is the only rule that keeps a call to action meaning anything.

why it is built this way

Logo rail

Rail items are real anchors: pointer cursor, a lift and full-opacity brand ink on hover and focus, and a rail that dims its other marks while one is hovered — so the wall reads as a set being scanned rather than several logos shouting at once. Resting ink is a theme-aware token, never a hard-coded opacity, which would stay dark on a dark page.

The marquee variant fades at both edges with a mask rather than a gradient overlay, so it works on any ground, and it pauses on hover — a moving logo you cannot click is a reasonable thing to be annoyed by. Reduced motion falls back to the static wrap with no mask. The mark shown is LeanWise's own mono mark standing in for customer artwork.

Feature grid

A cell that looks clickable must behave like it is. .lw-feature-interactive carries a pointer cursor, a surface tint, the wipe-in rule, an arrow that advances 3px, and a :focus-visible ring — hover and focus are the same treatment, so a keyboard user sees what a mouse user sees. All of it stands down under prefers-reduced-motion.

Role tokens, not palette tiers. The index reads --lw-brand-text and the rules --lw-brand-line, both theme-aware — which is why the dark grid above needs no per-element overrides, only the .lw-band-dark scope. A numbered tier like brand-50 does not re-point, and would stay a light tint on a dark page.

Story card

Anatomy. The shipped .lw-story parts: a brand-line spine on the quote, a mono cite, and the outcome promoted to .lw-story-result — amber soft tint behind the amber text tier (:1), both of which re-point on dark.

Both halves of that pair must re-point together — a dark -on text tier left on a light tint measures 1.75 and disappears. In the React component the block renders only when quote, person and role are all present — the no-fabrication rule, enforced at runtime rather than in review.

Steps — one drawing for three components

A company timeline, a roadmap and a numbered “how it works” were three components in the consumer, and nothing rendered them side by side to show they were the same drawing. They are one now, and it deliberately has no state axis: Stepper owns wizard state — done / current / upcoming, with the ARIA that goes with it. A timeline has none, because every entry already happened. The split is by meaning, not by looks.

The marker text is real markup, never CSS counter() — so it is selectable and announced, the same reason FeatureGrid writes String(i+1).padStart(2,"0"). The tile is --lw-brand-soft under --lw-brand-on, the pair CLAUDE.md singles out: --lw-brand-text is the link shade and measures 3.98 on this tint.

Quote — one spine, two selectors

The pull quote and the story card's quote share ONE declaration block. .lw-quote, .lw-story .lw-story-quote — the brand hairline is drawn once and owned once. A standalone testimonial cannot be expressed by StoryCard, whose quote only renders inside that composition; the moment it gets its own class, the spine has two owners unless they share the declaration. Sharing it is what stops a second treatment appearing.

This card loads two stylesheets, and that is the test

base.css + marketing.css, no product.css. Through v1.3.0 this card loaded all three, which is precisely why it could not see the defect v1.3.1 fixes: Avatar — which Byline renders and ArticleCard renders a Byline of — plus Tabs, Pagination and EmptyState were all in the app-surface layer. The specimen was loading the file the documented recipe tells a consumer to drop, so four marketing components rendered correctly here and unstyled in the flagship consumer, which had resorted to a ?url import of product.css on two public routes to get them back.

It caught a twelfth in v1.7.0: Table. The consumer publishes its measured extraction accuracy — one row per document type, every percentage beside the sample count it was measured on — on a marketing page. That table had rendered as bare UA markup since the split: no frame, no radius, no header face, no tabular figures, and no overflow-x: auto, which is the one that turns a wide table into a sideways page on a phone. The specimen above is the gate; the lesson is that a data display is not automatically an app surface — a page arguing from evidence has to show the evidence, and it does not get to load a different stylesheet to do it.

The hero is a dark BAND now, not just a navy background. .lw-hero-dark was never in tokens.css's band-selector list — .lw-section.dark escaped only because its class list literally contains dark. So every role token inside a hero resolved against the light palette on navy paper, and marketing.css hand-patched exactly the four elements anyone demos (.lw-h1, .lw-lead, .lw-eyebrow, .lw-btn-ghost). The Byline in the hero above is the specimen that had been missing: its name is --lw-fg (~1.5:1 on navy before the fix) and its role and date are --lw-fg-subtle (3.36:1). Both are axe serious, and both were invisible because no card had ever put a role-token consumer inside a hero.

Article chrome — composition, not new classes

There is no .lw-article grid and no .lw-post card. The article + contents layout is .lw-split, which already collapses at --lw-bp-lg; the index card below is .lw-card + CardHead/Body/Foot + .lw-byline inside a Grid. What was genuinely missing were the atoms: .lw-byline, .lw-article-head and .lw-pill-link.

The whole card is the link, so there is one tab stop — which is also why its tags are inert .lw-pills: a link inside a link is invalid and unreachable by keyboard. Tags become .lw-pill-link anchors on the article page itself, where they are the only link in their row.
