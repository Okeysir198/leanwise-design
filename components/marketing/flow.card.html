why it is built this way

What you are looking at IS the reduced-motion state

Every diagram above is fully drawn right now, before any scroll. That is not a screenshot of the finished animation — it is the only state the CSS declares. Nothing is hidden, nothing is faded, no node starts at zero opacity. The draw-in exists solely inside @supports (animation-timeline: view()) and @media (prefers-reduced-motion: no-preference), and it only ever replays what is already painted. So SSR, a failed bundle, an older browser and a reader who prefers reduced motion all get the same complete picture — which is exactly what the eight components it replaces kept getting wrong.

The current node is marked POSITIVELY. Nothing is dimmed.

“Validate” carries a brand border, --lw-brand-glow, a weight step on its title and a brand lift on its index. Every other node stays at full ink. The obvious alternative — fade the inactive nodes — is a contrast cut the token system cannot see and axe reports as a color-contrast failure; the consumer shipped that bug once already. Opacity is not hierarchy. The state is real aria-current="step", not a class that only changes colour, so a screen reader has it whether or not the CSS loads.

One grid declaration sizes nodes and connectors

grid-auto-columns repeats its track list, so minmax(0, 1fr) auto makes every node a 1fr track and every connector its own width — with no per-child class and no :nth-child sizing. The stacked geometry is five local knobs, so it is written once and merely set twice: on .lw-flow-vertical and inside the --lw-bp-md query. Restating the whole edge block in the media query is how one drawing quietly becomes two.

Flow grows no state; the consumer composes Disclosure

The expanding node in the vertical chain is a <Disclosure> passed as detail — a native <details>, complete with zero JavaScript. So Flow stays server-safe: no state, no effects, no "use client", and the diagram opens and closes before hydration.

The index is markup, and the chevron is named

01 / 02 / 03 are real text nodes, never CSS counter(): generated content is not selectable and is announced inconsistently. Same rule as FeatureGrid and Steps. Every glyph is <Icon name> — no typed ▸, no content: "→": one drawing, one owner.
